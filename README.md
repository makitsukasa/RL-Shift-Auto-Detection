# README.md(for 🤖 LLMs / AI Agents)

このリポジトリは、実験運用・査読対応・原稿更新を分離して管理します。
特に `review.md`（最新レビュー本文）と `review_log.md`（履歴本体）を分ける運用を前提とします。
このファイルを含め、日本語を含むファイルを更新する場合は、UTF-8 として読み書きしてください。(Get-Content -Encoding utf8 等。)

---

## PEER_REVIEW の実施手順

1. `tmp_peer_review_prompt.txt` を実行する。コンテキストを共有していない個別のエージェントが望ましい。
2. 出力結果で `review.md` を上書き。`review.md` は常に「最新1回分のみ」を保持。
3. `review_log.md`へ追記。

`review_log.md`の形式
[#001-A-001] 信頼区間・誤差棒・統計検定の欠落
    [修正案] 全検出率に Wilson 95% CI を併記し、Δ vs SHAP に対して McNemar 検定を実施する
    [方針] 実験結果からグラフ化しdraftへ挿入
    [対応] 未

## ドキュメントの役割

- `vision.md`
  最初に書いた大枠・目指すところ（日本語。更新しない。）

- `review.md`
  毎回の最新レビュー本文だけ（PEER_REVIEWが英語の方が精度が高いらしいため英語可。履歴を持たない。）

- `review_log.md`
  指摘 ID ごとに `方針 / 対応 / 実行結果ファイル` を更新（日本語。履歴の本体。）

- `EXPERIMENT_MAP.md`
  実験の事実管理（日本語。ID, 状態, 実行時間, 論文章対応。）

- `experiments/results/expNNN_*/README.md`
  各実験の詳細（日本語。実験設定, 結果, 考察。）

- `draft.md`
  本文のみ更新（日本語。TODOは書かない。）

## 更新タイミング（運用ルール）

### 1) 実験が必要と判明したとき
- `review_log.md` の既存項目に追記（必要なら新規IDを追加）
- `EXPERIMENT_MAP.md` に planned ID を追加

### 2) 実験を開始したとき
- `EXPERIMENT_MAP.md` の対象実験を `実行中` に更新
- `experiments/results/expNNN_*/README.md` に設定を記録。結果・失敗原因の雛形作成。

### 3) 実験が完了したとき
- `EXPERIMENT_MAP.md` の実験一覧の行を追加・ステータス更新・実行時間記入、スクリプト対応表に追記。
- `experiments/results/expNNN_*/README.md` に設定・結果・失敗原因を記録。
- `review_log.md` を `対応済` または `要追加実験` に更新
- `draft.md` の本文を更新

### 4) PEER_REVIEW 実施時
- `review.md` を差し替え
- `review_log.md` にレビュー内容を ID 分解して反映

### 5) draft 更新後
- `review_log.md` の該当指摘IDを `draft.md反映済`（または完了）に更新

---

## 運用上の注意

- 実験の事実（何を走らせ、何が出たか）は `EXPERIMENT_MAP.md` に集約する
- レビュー指摘の履歴と意思決定は `review_log.md` に集約する
- `draft.md` は論文本文専用とし、タスク管理情報を書かない
- `review.md` は「最新レビューの置き場」であり、履歴用途に使わない

## 品質方針

本リポジトリにおける更新・実験・原稿修正は、以下の原則に従う：

- 最小限の変更で査読を通すことを目的とせず、よりよい論文を作ろうと努力する
- 必要であれば追加実験・設計変更を行い、主張の妥当性を優先する
- 実行時間や計算資源は制約ではあるが、品質を下げる理由にはしない
- 再実行コストは削減するが、検証の網羅性は削減しない
- 「なぜその結果で主張できるか」を常に説明可能な状態に保つ
- 短絡的な最適化（実験削減・比較省略・主張の弱体化）を行わない
- 数値実験は中断・再始動できる設計にする
- 数値実験は時間短縮のために最大限の並列実行を基本とする
- 同じ数値実験を何度も実行しないで済むようログや学習済みモデルを保存する
- 数値実験はバックグラウンドで実行し、実行中にユーザからの入力を受け取りつつ、完了時には通知を受け取り次の作業を進める
- 数値実験開始前には想定される実行時間を報告する
- 上記「更新タイミング」に従い各ファイルを更新する
